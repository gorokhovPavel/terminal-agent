## 1.1 Что нужно от пользователя для AI Studio API

AI-помощник создаёт код подключения в этом уроке, но не получает секреты сам и не просит вставлять их в чат. Пользователь должен подготовить доступ в AI Studio и локально заполнить `.env`.

Нужны данные:

- `YANDEX_API_KEY`: secret value созданного API key. Если AI Studio показывает ID ключа и secret key, в `.env` кладём secret key. ID ключа не нужен в коде агента.
- `YANDEX_FOLDER_ID`: ID папки AI Studio / Yandex Cloud. Это не имя папки `default`, а строковый идентификатор folder ID.
- `YANDEX_MODEL_URI`: полный URI выбранной текстовой модели, например `gpt://<YANDEX_FOLDER_ID>/gpt-oss-120b/latest`. Это проектная переменная для готовой строки `gpt://{folder}/{model}`.
- `YANDEX_BASE_URL`: OpenAI-compatible endpoint `https://ai.api.cloud.yandex.net/v1`.

Что должен сделать человек:

1. Открыть AI Studio / Yandex Cloud.
2. Убедиться, что есть активная папка, доступная модель и при необходимости активный billing / trial.
3. Создать API key для вызова языковых моделей. Если интерфейс просит scope или permission, выбрать доступ на выполнение языковых моделей, например `yc.ai.languageModels.execute`, либо актуальный рекомендованный AI Studio вариант.
4. Сохранить secret key в безопасном месте.
5. Найти folder ID папки, в которой доступна модель.
6. Выбрать model URI из Model Gallery или списка доступных моделей.
7. Создать локальный `.env` по `.env.example` и вписать туда реальные значения.
8. Не отправлять реальные значения AI-помощнику, не вставлять их в `Plan.md`, README, заметки или код.

Что может спросить AI-помощник:

- создан ли локальный `.env`;
- какая модель выбрана, без секретов;
- какой smoke-check падает: авторизация, folder ID, model URI, сеть или quota.

Что AI-помощник не должен спрашивать:

- реальный `YANDEX_API_KEY`;
- содержимое `.env`;
- номер карты, billing-данные или личные данные аккаунта.

Минимальный `.env` локально:

```
YANDEX_API_KEY=<secret_key_value>
YANDEX_FOLDER_ID=<folder_id>
YANDEX_MODEL_URI=gpt://<folder_id>/gpt-oss-120b/latest
YANDEX_BASE_URL=https://ai.api.cloud.yandex.net/v1
YANDEX_TEMPERATURE=0.4
YANDEX_MAX_TOKENS=10000
```

## 1.2 Целевой сценарий

Агент должен пройти один локальный маршрут:

1. Пользователь запускает `python main.py`.
2. Терминал показывает prompt `agent>`.
3. Пользователь просит прочитать `workspace/lesson.md`, сделать summary и сохранить `notes/lesson_summary.md`.
4. Runtime отправляет модели system prompt из `agent/soul.md`, задачу и список двух tools.
5. Модель выбирает `read_markdown_file`.
6. Runtime проверяет путь, расширение и границы `workspace/`.
7. Python читает разрешённый Markdown-файл.
8. Модель делает summary сама, без отдельного summary-tool.
9. Модель выбирает `write_note`.
10. Runtime проверяет путь, расширение и границы `notes/`.
11. Python сохраняет `notes/lesson_summary.md`.
12. Модель возвращает финальный ответ пользователю.
13. В терминале виден лог задачи, tools, чтения, записи и финального ответа.

Второй сценарий:

1. Пользователь просит ответить на вопрос по `workspace/lesson.md`.
2. Runtime читает файл через `read_markdown_file`.
3. Модель отвечает по содержанию.
4. `write_note` не вызывается.

Сценарий контекста текущей REPL-сессии:

1. Пользователь просит прочитать `workspace/lesson.md` и коротко ответить на вопрос.
2. Runtime сохраняет user-сообщение, tool-call, tool-result и assistant-ответ в in-memory `conversation_history`.
3. Следующим вводом пользователь просит сохранить предыдущий ответ в `notes/session_context_check.md`.
4. Модель видит предыдущий ответ в контексте текущей сессии и выбирает `write_note`.
5. Runtime записывает заметку через разрешённый tool.
6. После выхода из `python main.py` история исчезает.

Негативные сценарии:

1. `.env` не раскрывается.
2. Путь вне `workspace/` не читается.
3. Не-`.md` файл не читается.
4. Несуществующий файл даёт понятный отказ.
5. Shell-команда не выполняется.

## 2. Требования к результату

- `spec.md` описывает agent runtime contract 5.9.1:
  - локальный терминальный интерфейс;
  - Python runtime;
  - `ai_client.py`, созданный в этом уроке для AI Studio API;
  - `agent/soul.md` как system prompt;
  - ровно два tools: `read_markdown_file` и `write_note`;
  - agent loop: задача -> model call -> tool-call -> runtime validation -> Python tool -> tool result -> final answer;
  - контекст текущей терминальной сессии хранится в памяти процесса и передаётся в следующие model calls внутри REPL;
  - summary не является отдельным tool;
  - ограничения и отказы описаны до кода.
- `Plan.md` ведёт работу по циклу `Spec -> Plan -> AGENTS.md -> Work -> Check -> README`.
- `AGENTS.md` ограничивает ИИ-помощника учебным агентом и активным пунктом плана.
- `requirements.txt` содержит только минимальные зависимости для текущего runtime.
- `.env.example` содержит имена переменных без реальных секретов.
- `.env` создаётся пользователем локально и содержит реальные `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `YANDEX_MODEL_URI`, `YANDEX_BASE_URL`, `YANDEX_TEMPERATURE`, `YANDEX_MAX_TOKENS`.
- `ai_client.py` возвращает сообщение модели целиком, чтобы runtime видел `tool_calls`.
- `tools.py` проверяет относительные пути, расширение `.md` и выход за разрешённые папки.
- `agent_runtime.py` содержит ограниченный loop с `MAX_STEPS` и принимает `conversation_history`.
- `main.py` запускает простой терминальный REPL, хранит `session_messages` в памяти текущего процесса и передаёт их в `run_agent`.
- `workspace/lesson.md` даёт локальный Markdown для проверки.
- `README.md` / runbook обновляется в конце по фактическим командам и результатам.
