# spec.md — Terminal Agent

## Назначение

Учебный локальный терминальный агент. Принимает задачу в терминале, вызывает языковую модель, выполняет разрешённые tools и сохраняет заметку с итогом. Весь цикл виден в логе терминала.

---

## Результат урока

- Локальный агент запускается командой `python main.py`.
- Системная инструкция агента хранится в `agent/soul.md`.
- Языковая модель вызывается через `ai_client.py`.
- Цикл «думать → выбрать tool → выполнить → ответить» реализован в `agent_runtime.py`.
- Разрешённые tools реализованы в `tools.py`.
- Агент читает только `.md`-файлы внутри `workspace/`.
- Агент пишет только `.md`-файлы внутри `notes/`.
- Summary делает модель после чтения файла — отдельного summary-tool нет.
- В терминале виден лог: задача, выбранный tool, прочитанный файл, записанная заметка или отказ.

## Файловая структура

```
terminal-agent/
├─ main.py              — точка входа: ввод задачи, запуск runtime, вывод ответа
├─ ai_client.py         — вызов языковой модели (API-ключ из .env)
├─ agent_runtime.py     — цикл: system prompt + история + tool calls
├─ tools.py             — реализация read_markdown_file и write_note
├─ requirements.txt     — внешние зависимости
├─ .env                 — секреты (не в git)
├─ .env.example         — заглушки переменных окружения
├─ AGENTS.md            — правила агента для этого урока
├─ Plan.md              — шаги и статус
├─ README.md            — команды запуска и проверки
├─ spec.md              — этот файл
├─ agent/
│  └─ soul.md           — системная инструкция агента
├─ workspace/
│  └─ lesson.md         — учебный файл для чтения агентом
└─ notes/
   └─ lesson_summary.md — заметка, созданная агентом
```

## Как работают tools (agent runtime contract)

Модель **не читает файлы и не выполняет функции сама**. Она возвращает structured tool-call: имя функции и аргументы в JSON. Python runtime:

1. Получает tool-call от модели.
2. Проверяет имя функции по белому списку.
3. Проверяет аргументы (путь, расширение, границы директории).
4. Если проверка прошла — выполняет функцию и возвращает результат модели.
5. Если проверка не прошла — возвращает модели сообщение об ошибке; модель сама решает что делать дальше.

Модель никогда не получает прямой доступ к файловой системе, сети или интерпретатору.

## Разрешённые tools

| Tool | Что делает | Жёсткая граница |
|------|-----------|----------------|
| `read_markdown_file(path)` | Читает Markdown-файл из `workspace/` | Только относительный путь, только `.md`, только внутри `workspace/` |
| `write_note(filename, content)` | Создаёт или перезаписывает Markdown-заметку в `notes/` | Только относительный путь, только `.md`, только внутри `notes/` |

## Переменные окружения

| Переменная | Обязательная | Описание |
|-----------|:---:|---------|
| `YANDEX_API_KEY` | ✅ | Secret key от AI Studio |
| `YANDEX_FOLDER_ID` | ✅ | ID папки в Yandex Cloud |
| `YANDEX_MODEL_URI` | ✅ | Полный URI модели, напр. `gpt://<folder_id>/gpt-oss-120b/latest` |
| `YANDEX_BASE_URL` | ✅ | `https://ai.api.cloud.yandex.net/v1` |
| `YANDEX_TEMPERATURE` | нет | Температура (по умолчанию `0.4`) |
| `YANDEX_MAX_TOKENS` | нет | Максимум токенов (по умолчанию `10000`) |

`.env.example`:
```
YANDEX_API_KEY=put_your_secret_key_here
YANDEX_FOLDER_ID=put_your_folder_id_here
YANDEX_MODEL_URI=gpt://<folder_id>/gpt-oss-120b/latest
YANDEX_BASE_URL=https://ai.api.cloud.yandex.net/v1
YANDEX_TEMPERATURE=0.4
YANDEX_MAX_TOKENS=10000
```

## Запреты (расширять нельзя)

- Не добавлять Telegram-интерфейс.
- Не добавлять MCP, web UI, SQLite, долгосрочную память или внешние сервисы.
- Не выполнять shell-команды.
- Не читать `.env` через tools или агента.
- Не ходить в интернет.
- Не работать с произвольными файлами проекта вне `workspace/` и `notes/`.
- Не добавлять больше двух tools.
- Не превращать агента в универсального помощника.

## Критерии готовности

**Главный сценарий:**
1. Пользователь даёт задачу: «Прочитай `workspace/lesson.md` и сохрани summary в `notes/lesson_summary.md`».
2. Агент вызывает `read_markdown_file("workspace/lesson.md")`.
3. Модель делает summary и вызывает `write_note("lesson_summary.md", "...")`.
4. В терминале виден лог каждого шага.
5. Файл `notes/lesson_summary.md` создан.

**Второй сценарий:**
1. Пользователь даёт задачу: «Прочитай `workspace/lesson.md` и ответь на вопрос».
2. Агент читает файл и отвечает — без записи заметки.

**Отказы (агент должен отклонять):**
- Чтение `.env` → отказ.
- Путь вне `workspace/` → отказ.
- Файл не `.md` → отказ.
- Несуществующий файл → сообщение об ошибке модели.
- Shell-команда → отказ.

**Безопасность:**
- В коде, заметках и README нет секретов.
- `.env` не попадает в git.

---

## Границы (что не делаем в этом уроке)

- Нет доступа к файловой системе за пределами `workspace/` и `notes/`.
- Нет запуска shell-команд, сетевых запросов, работы с БД.
- Нет веб-интерфейса, API, деплоя.
- Нет авторизации, ролей, мультипользовательского режима.
- Нет автономного цикла без участия пользователя (один запрос → один ответ).
- Нет инструментов кроме `read_markdown_file` и `write_note`.
- Summary не выделяется в отдельный tool — это задача модели.
